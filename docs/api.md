# API

Публичная часть описана в OpenAPI 3.1: спека `apps/api/internal/api/openapi.yaml`,
на сервере отдаётся как `GET /api/v1/openapi.yaml`, интерактивная документация — `/api/v1/docs`
(например, https://m3105.ru/api/v1/docs).

Бэкенд: Go, префикс `/api/v1`. Все ответы JSON, время в RFC 3339 (UTC), даты
без времени — `YYYY-MM-DD`. Ошибки:

```json
{ "error": "Проверьте заполнение полей", "code": "validation", "fields": { "title": "Укажите название" } }
```

Коды: `validation` (422), `not_found` (404), `conflict` (409), `unauthorized` (401),
`bad_password` (401), `rate_limited` (429), `internal` (500).

## Авторизация

`POST /auth/login` с `{ "password": "…" }` ставит HttpOnly-куку `edu_session`
(сессия в Valkey, 30 дней). `POST /auth/logout`, `GET /auth/me`. Десять попыток
входа за 15 минут с одного IP (считаются все, не только неверные) блокируют вход
на это окно.

Если задан `ADMIN_API_TOKEN`, админские эндпоинты принимают также заголовок
`Authorization: Bearer <token>` — без входа и сессии, для скриптов
(`scripts/content.ts`). `GET /auth/me` с токеном тоже отвечает 200.

## Админка (`/admin/*`, требует куку)

`GET/PUT /admin/settings`, `GET /admin/overview` и стандартный CRUD для
`subjects`, `labs`, `events`, `pages`, `notes`, `quizzes`:
`GET /`, `POST /`, `GET /{id}`, `PUT /{id}`, `DELETE /{id}`.
Квиз обязательно привязан к конспекту (`noteId`), предмет берётся из него; на сайте квизы показываются под конспектом. `POST /admin/quizzes/validate` проверяет массив вопросов и возвращает
нормализованный вариант. Слаги генерируются из названия транслитерацией и
дедуплицируются автоматически.

Формы ввода описаны в `apps/web/lib/api/types.ts` (`*Input`) и в
`apps/api/internal/models/models.go`.

## Аудитория

У предметов, лаб, конспектов, событий и сдач есть `audience` — для кого материал: метки `stream:<номер>`
(весь поток) и `group:<группа>`; пустой список — для всех. Квизы следуют аудитории своего конспекта.
Списки (`/home`, `/subjects`, `/subjects/{slug}`, `/labs`, `/notes`, соседи в `/notes/{subject}/{slug}`, `/quizzes`,
`/calendar`, `/calendar.ics`, `/practice`) принимают `?for=<группа>`: остаются материалы для всех, для этой группы и для
её потока (поток берётся из списка курса). Без параметра — всё; страницы отдельных лаб и конспектов открыты всем.
Бот рассылает новую лабу и напоминает о дедлайнах только тем, чьей группе она адресована (чат без аккаунта получает всё).
Админка: поле `audience` во входных данных этих сущностей, `GET /admin/study-groups` — группы списка курса с потоками.

## Ответственные

Студент может отвечать за поток (`stream:N`) или группу (`group:G`). С такой ролью он входит в админку своим
аккаунтом (кука `edu_user`, без пароля): `GET /auth/me` отвечает `{ role: "editor", editor: { userId, userName, scopes, zone } }`,
где `zone` — роли плюс группы их потоков. Ответственному доступны лабы, конспекты, квизы (по конспекту), события и сдачи
(включая очередь, регулярные правила, отмену и перенос занятий), загрузка файлов, чтение предметов и групп; остальное — 403 `forbidden`. Создавать, править и удалять можно
только материалы, у которых аудитория непустая и целиком внутри зоны (иначе 403 `outside_zone`); списки показывают только их.
Автор лаб и конспектов — `authorId`/`authorName`: ответственный становится автором того, что создаёт; админ выбирает автора в форме.

| Метод | Путь | Описание |
| ----- | ---- | -------- |
| GET | `/admin/editors` | роли (ответственному — только своей зоны) |
| GET | `/admin/editors/candidates` | подтверждённые студенты, которых можно назначить |
| POST | `/admin/editors` | `{ userId, scope }` — админ назначает любого, ответственный за поток — только за группы своего потока |
| DELETE | `/admin/editors/{id}` | снять роль (те же права) |
| GET | `/admin/journal?entity=` | журнал правок со снимками `before`/`after` (ответственному — своей зоны) |
| POST | `/admin/journal/{id}/revert` | только админ: создание удаляется, правка возвращает прежнюю версию, удаление создаёт материал заново |

О каждой правке ответственного бот пишет админу со ссылкой на журнал.

## Аккаунты студентов

Без паролей: аккаунт создаётся при первом входе через Telegram Login Widget;
пасскей (WebAuthn) добавляется в профиле и затем работает как второй способ входа.
Новый аккаунт не подтверждён (`approved: false`, `groupName` пустой): профиль и чтение доступны, а запись на сдачи,
отметки лаб и комментарии отвечают 403 `not_approved`. Подтверждает аккаунт сам студент — выбирает себя
в списке курса (таблица `students`, её загружает админ): аккаунт получает `isu`, `displayName` «Имя Фамилия» и группу
из списка, и сменить их сам уже не может. Строку, которую выбрал другой аккаунт, не предлагают и выбрать нельзя
(409 `student_taken`), второй выбор — 409 `already_claimed`. О каждом выборе бот пишет админу с кнопкой «отвязать»
(`unclaim:<id>`); отвязанный аккаунт снова не подтверждён и выбирает заново.
Имя (`name`) — это `displayName`, иначе `telegramName`, который обновляется при каждом входе через Telegram.
Сессия — HttpOnly-кука `edu_user`, 30 дней в Valkey.

### Регулярные сдачи

Правило (`practice_rules`, `store/practice_rules.go`, `api/practice_rules.go`) — «предмет, день недели, время
начала и конца по времени сайта, недели (`all`, `odd`, `even`), период `startsOn`–`endsOn` (не больше года),
место, `capacity`, заметка, аудитория». Занятия по нему — обычные строки `practice_sessions` со своим `id`,
очередью, заморозкой и обменами, созданные сразу при сохранении правила (`rule_id` + `occurs_on`); планировщика
нет. Чётность недель — от `semesterStart`/`firstWeekParity` (`internal/schedule`, `internal/semester`); без начала
семестра чётные и нечётные недели не выбрать (422 по полю `weeks`).

Сохранение правила трогает только будущее:

- нет занятия на дату — создаётся; разовая сдача того же предмета с той же аудиторией на эту дату
  привязывается к правилу вместе с записями (так старые сдачи переходят на правило; если время, место,
  лимит или заметка у неё другие, она становится «изменённой вручную»); прошедшие разовые тоже
  привязываются — для истории, но не меняются;
- занятие правила без ручных правок обновляется по правилу; изменённое вручную (`overridden`) и
  отменённое не трогаются;
- даты, которой больше нет в правиле: без записей — занятие удаляется, с записями — отменяется
  (причина «Занятие убрано из расписания», бот пишет записавшимся), изменённое вручную с записями
  становится разовым.

Удаление правила убирает будущие занятия без записей; прошедшие и с записями остаются разовыми.

| Метод | Путь | Описание |
| ----- | ---- | -------- |
| GET, POST | `/admin/practice-rules` | правила (с `sessionsCount`, `upcomingCount`, `canceledCount`, `next` — ближайшие начала); создать |
| GET, PUT, DELETE | `/admin/practice-rules/{id}` | правило |
| POST | `/admin/practice-rules/preview` | `{ id?, rule }` → `[{ day, startsAt, endsAt, action, sessionId, signups, differs }]`: что сохранение сделает с каждой датой (`create`, `adopt`, `update`, `keep`, `manual`, `canceled`, `past`, `delete`, `cancel`, `detach`) |
| POST | `/admin/practice/{id}/cancel` | `{ reason, moveSignups }` — отменить одно занятие. Строка остаётся (`canceled`, `cancelReason`): правило её не пересоздаст, студенты видят отмену на сайте, в календаре и ICS (`STATUS:CANCELLED`). Ждущие обмены удаляются, бот пишет записавшимся со ссылкой на следующую сдачу. С `moveSignups` записи переезжают на следующую неотменённую сдачу предмета для той же аудитории с прежним временем записи (422, если её нет) |

Перенос или другой лимит одного занятия — обычный `PUT /admin/practice/{id}`: занятие правила становится
`overridden`; если поменялись время или место, бот пишет записавшимся. Отменённые занятия не участвуют в
переносе резерва и в «Не успел в прошлый раз» — предыдущей считается последняя неотменённая сдача.

Теормин. У предмета с `theoryMin` (переключатель в форме предмета) на сдаче можно отметиться на теормин по
любой опубликованной лабе (`practice_theory_signups`). Отметка не входит в очередь, `capacity`, резерв, обмены
и пропуск: это только подсчёт, сколько придёт на теормин (менторы) и сколько на защиту (практики). В ответе
сдачи — `theoryMin`, `theoryCount` (отметок студент × лаба), `theory` (кто и по каким лабам, в порядке записи) и
`myTheoryLabIds`; `signupsCount` по-прежнему считает только студентов с защитами. Без флага у предмета —
422 по `theoryLabIds`. Отметки на теормин переезжают при отмене с переносом, держат занятие правила от удаления,
их владельцы получают сообщения бота о переносе и отмене; в профиле — `theoryLabs`, в админке — `theory` в
`/admin/practice/{id}/signups`.

Очередь сдачи (`internal/queue`, `store/practice_queue.go`) состоит из защит — студент с одной лабой:

1. Первыми идут защиты, оставшиеся в резерве предыдущей сдачи того же предмета (места сверх `capacity`
   в её сохранённом порядке). Кто оставался в резерве несколько сдач подряд (`missed`), идёт раньше
   тех, кто один раз; при равенстве — в порядке прошлого резерва. Цепочка считается назад по сдачам
   предмета, пока защита была в их резерве.
2. Дальше по кругам: у каждого студента сначала его самая новая лаба, вторая — после первых лаб всех.
   Внутри круга новее лаба раньше, при равенстве — жребий, закреплённый за парой (сдача, студент).
   Время записи на место не влияет.
3. В 20:00 накануне (`queue.FreezeAt`, таймзона из настроек) порядок замораживается: при первом чтении
   или записи после этого момента он пишется в `queue_pos` (`queue_frozen_at`). Поздние записи получают
   следующий номер из последовательности и встают в конец по времени записи; отмена только сдвигает
   остальных. До заморозки порядок считается на лету и в базу не пишется.
4. Ручная перестановка в админке (`queue_manual`) тоже сохраняет порядок, дальше только дописываем.
5. По сохранённому порядку (`frozen` в ответе) студент может уйти в конец («В конец очереди», пропустить всех вперёд) — его защиты получают
   новые номера из последовательности и встают в конец — или поменяться местами с согласия другого
   (`practice_swaps`). Запрос помнит `queue_pos` обеих защит: если к согласию очередь сдвинулась
   (пропуск, другой обмен, правка админа), обмен не проводится и запрос удаляется. Пропуск и обмен
   отменяют ждущие запросы своих защит; «Автоматически» в админке пересчитывает очередь по правилам
   и сбрасывает и то и другое.
6. «Не успел в прошлый раз» (`not_reached_at`): по сохранённому порядку студент переносит защиты лаб,
   с которыми был записан на предыдущую сдачу предмета, в начало — сразу за ведущей группой переносов
   из резерва и тех, кто отметился раньше; остальные сдвигаются, сохраняя порядок. Защиты получают
   метку `notReached`, видную всем. Ждущие обмены этих защит удаляются, остальным обновляются места
   (обе стороны сдвинулись вместе). «Автоматически» в админке метки сбрасывает.

Модерация: `GET /admin/comments` (последние 200 с `targetTitle` и `targetPath`), `PUT /admin/comments/{id}`
(`{ body, attachmentIds? }` — текст и файлы любого комментария), `DELETE /admin/comments/{id}` — админ правит и удаляет любые комментарии.

## Баллы

Источник баллов (`grade_sources`) — Google-таблица, открытая по ссылке на просмотр: вкладки — группы,
строки — студенты, столбцы ищутся по заголовкам (`nameColumn`, `idColumn`, `totalColumn`, `groupColumn`,
разбивка `columns: [{ key, header, label, max }]`). API берёт список вкладок из HTML-вида таблицы
(`/htmlview`), каждую вкладку — CSV-экспортом, вкладки без нужных заголовков или не подходящие под
`tabPattern` пропускает. Заголовок совпадает целиком или как начало более длинного («ЛР1» находит
«ЛР1 (база)»), `#N` — N-й столбец, если у него нет заголовка. Группа строки — из `groupColumn`, иначе из
последней строки-разделителя (в строке только код группы, например `M3105`), иначе название вкладки.
Если задан столбец ИСУ, строки без номера пропускаются (так отсекаются строки вроде «max число баллов»).
Строка максимумов — без номера ИСУ, с ячейкой «max», «макс», «максимум» отдельным словом («max число
баллов» в столбце ФИО под заголовком или «:max» сбоку над ним; «Максимов» не считается): при каждом синке они
перезаписывают `max` у столбцов разбивки (преподаватели меняют нумерацию лаб и баллы за них по ходу
семестра). Берётся первая вкладка, где столбец есть; столбцы без значения в этой строке сохраняют
максимум из настроек.
Заголовок ищется в строке с ФИО и в строках над ней (ближайшая первой), так что групповые заголовки
вроде «Total for the semester» строкой выше тоже находятся. Пустой итог (или незаданный `totalColumn`)
считается суммой разбивки; столбца нет на вкладке — этой части у строки нет вовсе (ключ не
приходит), пустая ячейка — `null`. Синк (`internal/grades`) раз в `syncHours` целиком заменяет строки источника
(`grade_rows`); при ошибке старые строки остаются, текст ошибки — в `syncError`, повтор через 30 минут.
Фоновый синк выключается `GRADES_SYNC=false` (при нескольких инстансах API оставить на одном).

Лабы с модификаторами (`scheme`, как в таблице ОП): у лабы слева от её итога блок столбцов — баллы за
теормин (`theory`, «12»), плюсы (`plus`, «+»), минусы (`minus`, «-»), ступень просрочки (`late`, «D»).
Блок ищется у каждого столбца разбивки отдельно: подряд идущие слева столбцы с этими заголовками
(пустые пропускаются), до первого чужого заголовка или повтора, поэтому одинаковые «+» у пяти лаб не
путаются, а у «Live» или «Экзамен» блока нет. Ячейки хранятся в `grade_rows.details`. Лаба даёт
`теормин × (1 + bonusPercent% × (плюсы − минусы)) × lateFactors[ступень]` (дальше последней ступени —
последний коэффициент, ниже нуля не опускается; плюсы и минусы бывают дробными). Статус: есть теормин —
`done`; нет теормина, но есть ступень или модификаторы — `accepted` (лаба принята, баллов не даёт,
`potential` — сколько даст после зачёта по теормину, считая теормин равным максимуму столбца); иначе `none`.
Теормин — зачёт, пересдавать его можно сколько угодно: до зачёта ячейка пустая, после — в ней баллы за
лабу без модификаторов. Расчёт — `GradeScheme.Lab` в
`internal/models`, в `/grades` и профиле — поле `labs`. Синк сверяет итоги лаб в таблице со схемой и
возвращает расхождения в `warnings` (преподаватель поменял правила). Бот пишет и о том, чего не видно
по баллам: лаба принята без теормина, новые плюсики или минусы, следующая ступень просрочки
(`notified_details`); в `/grades` — какие лабы ждут теормина.

`membersOnly` — таблица одной небольшой группы (например, языковой по английскому): источник видят
только студенты, чей ИСУ в ней есть, места считаются внутри таблицы, без учебных групп.

Строка связывается с аккаунтом по номеру ИСУ (`users.isu`). Номер ставит студент в профиле, админ или
автосопоставление после синка и после правки аккаунта: подтверждённому аккаунту без номера (`isu IS NULL`)
достаётся номер строки, если все слова его имени есть в ФИО, группа совпадает и совпадение единственное
с обеих сторон. Отвязанный вручную номер хранится как `''` и автоматически не возвращается.

| Метод | Путь | Описание |
| ----- | ---- | -------- |
| GET | `/grades?source=` | `{ sources, source, rows, myGroup, linked }`: все строки источника (`name` — «Фамилия Имя», без номеров ИСУ), `user` — аккаунт на сайте, `me` — своя строка; места считает фронт. Открыт всем, со студенческой кукой помечает свою строку, без неё `myGroup` — группа сайта |
| — | `/auth/user/me` → `grades` | свои результаты по источникам с местами `course`, `inGroup`, `site` (среди привязанных аккаунтов) |
| CRUD | `/admin/grade-sources` | `spreadsheet` принимает ссылку или id таблицы; в ответе `rowsCount`, `linkedCount`, `syncedAt`, `syncError` |
| POST | `/admin/grade-sources/{id}/sync` | синхронизировать сейчас: `{ tabs, skipped, rows, linked }`, при ошибке 502 `sync_failed` |

Бот сравнивает строки привязанных аккаунтов с тем, что студент видел в прошлый раз (`notified_total`,
`notified_parts`), и пишет об изменении с разбивкой по столбцам; первый импорт строки уведомлением
не считается. Команда `/grades` (кнопка «🎓 Баллы») — свои баллы и места.

## Вложения

Файлы лежат в S3-совместимом хранилище (MinIO в `docker-compose.yml`, в `devapi` — каталог рядом
с данными Postgres), описание — в таблице `attachments`. Отдаёт файлы сам API по адресу из поля
`url` (`/api/v1/files/{id}/{транслит имени}`), поэтому бакет приватный и работают права.

- Загрузка — `multipart/form-data` с полем `file`, ответ — `Attachment` `{ id, url, name, contentType, size, width, height, createdAt }`.
  Студент (`POST /files`, подтверждённый аккаунт): JPG, PNG, GIF, WebP и PDF до 10 МБ, не больше 30 файлов
  за 12 часов (429 `rate_limited`). Админка (`POST /admin/files`): любые файлы до 50 МБ; тот же файл
  повторно не сохраняется — возвращается уже загруженный (200 вместо 201).
- Тип определяется по содержимому, имя и `Content-Type` браузера не учитываются. У JPEG, PNG и WebP
  вырезаются EXIF, XMP и текстовые блоки (там бывают координаты), ориентация фото сохраняется;
  `width`/`height` — уже с учётом поворота. Картинки больше 60 мегапикселей отклоняются.
- Прикрепление: `attachmentIds` в комментарии — только свои файлы, ещё ни к чему не прикреплённые
  (иначе 422 по полю `attachmentIds`), не больше 6. Файлы удаляются вместе с комментарием или
  аккаунтом; загруженные, но так и не прикреплённые — через сутки. Объекты без строки в базе раз в час
  подчищает сборщик мусора (`files.RunGC`).
- Доступ: незаконченную загрузку видит только автор, остальное публично. Недоступное отвечает 404. Картинки, PDF, видео и аудио
  открываются в браузере, прочее отдаётся как вложение; у всего, кроме PDF, заголовок
  `Content-Security-Policy: … sandbox`, так что SVG или HTML не выполнят скрипт на домене сайта.
  Публичные файлы кешируются навсегда (`immutable`: по id содержимое не меняется).
- Превью: `?w=160|320|640|1280|1920` у JPEG, PNG и WebP — уменьшенная копия от imgproxy (WebP, если он есть
  в `Accept`; `Vary: Accept`). Права проверяются до imgproxy, он сам наружу не открыт. Картинка уже нужной
  ширины, GIF, SVG, `?download=1`, недоступный imgproxy — всё это отдаёт оригинал.
- Админка: `GET /admin/files` — последние 500 файлов с `place` (`content` — для текстов,
  `comment`, `pending`), автором, ссылкой на комментарий и `usedIn` — где на файл
  ссылаются тексты конспектов, лаб, страниц и предметов; `DELETE /admin/files/{id}` удаляет любой файл.
  `POST /admin/files?scope=social` грузит файл для чужого комментария: его можно передать в
  `attachmentIds` в `PUT /admin/comments/{id}`, в тексты он не попадает и повторно
  не переиспользуется. Админ (кука или Bearer) видит любые файлы, включая незаконченные загрузки.
- Без `S3_ENDPOINT` и `FILES_DIR` загрузка отвечает 503 `files_disabled`.

`GET /admin/search-queries?days=30&limit=50` — аналитика поиска: что искали, сколько раз и сколько раз
не нашли ничего. Промежуточные запросы «по мере набора» отфильтрованы, хранится только сам текст запроса.
При удалении конспекта или лабы их комментарии удаляются вместе с ними.
Сдачи и события попадают в календарь и ICS вместе с дедлайнами лаб (поле `source`: `lab`, `event`, `practice`), а ещё показываются на главной в блоке «События» и на странице «Сдачи».

## Проверка C++

`POST /cpp/check` с `{ code }` — один файл `main.cc`, `-std=c++20 -Wall -Wextra`, до 64 КБ (413 `too_large`).
Ответ: `formatted` — код после `clang-format --style=Google`, `diagnostics` — замечания clang-tidy
(конфиг — `internal/cpplint/google.clang-tidy`: `google-*`, имена по Google, `bugprone-*`, `performance-*`,
`modernize-*` и др.) и по одному замечанию `clang-format` на каждую строку, которую он поменял бы.
Позиции с 1, столбцы в UTF-16 (как в Monaco); `fixes` — правки, которые предлагает clang-tidy.

Инструменты цитируют прочитанные файлы, поэтому:

- `#include` — только `<…>` или `"…"` с относительным путём без `..`; имена из макросов и `#embed` — 422 `forbidden_include`;
- в ответ попадают только замечания по `main.cc`, сообщения о других файлах отбрасываются;
- в production инструменты работают не в API, а в контейнере `cpplint` (`cmd/cpplint`, `CPPLINT_URL`) без секретов и сети;
  вне production без `CPPLINT_URL` API запускает clang-format и clang-tidy сам, если находит их (`CLANG_FORMAT`/`CLANG_TIDY`, `PATH`, Homebrew LLVM).

Одновременно идут 2 проверки (`CPPLINT_PARALLEL`), остальные ждут до 10 с и получают 503 `busy`; на запуск инструмента 15 с (422 `timeout`).
nginx пускает 30 запросов в минуту с IP.
